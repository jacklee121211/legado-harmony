## 2. 最终实现（当前代码）

### 2.1 dock = 顶栏同款自绘胶囊
`ReaderPage3.readerDockBar()`：
```ets
Row() { ForEach(this.barActions(), (a, i) => { this.ReaderBarItem(a, i) }) }
  .height(READER_BAR_HEIGHT /*60*/).width('calc(100% - 32vp)')   // 左右各 16vp
  .borderRadius(30).clip(true)
  .backgroundColor(this.colorMode == 0 ? 'rgba(31,31,31,0.86)' : 'rgba(250,250,250,0.90)')
  .margin({ bottom: this.bottomRectHeight + READER_BAR_BOTTOM_GAP /*10*/ })
  .transition(TransitionEffect.move(TransitionEdge.BOTTOM).animation(UiMotion.transitionParam()))
```
- `HdsTabs` / 原生 `Tabs` 两个分支、`dockHdsController`、`dockHdsStyleModifier`、HDS import **全部删除**；
- `ReaderBarItem` 根 Column 加 `.layoutWeight(1)`（5 格等分）；
- 盒高仍 = `60 + 10 + bottomRectHeight` ⇒ 位置不漂。

### 2.2 阅读器弹窗 = 显式底色
- `ImmersiveMaterialUtil` 新增 `READER_PANEL_NIGHT_BG='rgba(31,31,31,0.96)'` / `READER_PANEL_DAY_BG='rgba(250,250,250,0.98)'`；
- 10 处 `systemMaterial` 删除；目录/书签/听书/设置/字体/材质/方案/保存配色/睡眠定时/VIP 全部按**阅读器本地** `readerColorMode` 画底；
- `TtsControlPanel` **让出背景**（否则同一半透明色 alpha 叠两层）；
- 共享组件 `VipDialog` 加 `@Prop readerPanel=false`，默认 `false` ⇒ 书架/我的/字体管理行为不变。

### 2.3 模糊材质的「蒙版颜色」也必须显式指定（第二轮，`59a4fa8`）
**这是同一根因的第二副面孔**：`backgroundBlurStyle` 的蒙版颜色默认跟**整机**走。
SDK 原文（`sdk/default/openharmony/ets/component/common.d.ts`）：
`BackgroundBlurStyleOptions.colorMode?: ThemeColorMode;`「Default value: **ThemeColorMode.SYSTEM**」，
`ThemeColorMode.SYSTEM = 0`「System color mode.」。
⇒ 「系统暗 + 阅读器亮」时，阅读器三元底色上被压一层**暗蒙版** = 用户看到的「材质不对、变黑」。

已修：
- 上下章节**进度胶囊** `.backgroundBlurStyle(…, { colorMode: 阅读器档位 })`；
- `MaterialDockModifier` 里写死的 `ThemeColorMode.SYSTEM` 改为**构造参数**（目录/书签两处都传阅读器档位）；
- 同机制漏网一并修：设置页「亮度/随系统/常亮」三处 `Text`（原来没有 fontColor）、书签/目录三按钮的
  **svg 图标**（`app.media.top/down` 源文件写死 `fill="black"`）+ `SymbolSpan`/`Text` 字色、目录搜索栏
  （`fontColor`/`placeholderColor`/`backgroundColor`）、睡眠定时（标题/时/分/两个 `TextPicker` 的
  `textStyle`/`selectedTextStyle`/`disappearTextStyle`）、保存配色标题、「正在排版…」占位（不再读
  `NightMode.isDarkSurface()`，改 `this.colorMode` + `pageBaseColor()`）。

**通用规律（下一位直接照用）**：凡是「系统按整机模式给的默认值」，在阅读器里都要显式覆盖：
`backgroundBlurStyle.colorMode`、组件默认 `fontColor`/`fillColor`、`ThemeColorMode`、HDS 的 bar 底色与蒙层。

## 3. 为什么“顶栏从来不坏”（照抄它的理由）

`ReaderPage3.ets` 顶栏（约 9196-9200）：
```ets
.backgroundColor(this.colorMode == 0 ? 'rgba(31,31,31,0.86)' : 'rgba(250,250,250,0.90)')
```
- 亮暗来源是**阅读器自己的** `colorMode`，不读 `NightMode.isDarkSurface()`（全局）；
- **不碰系统材质**，自己画半透明实底；
- 于是：既跟随阅读器日/夜间，又不会被“全局模式 / 一镜到底转场”带偏；四档阅读方式下都正常。
- 该处注释里有官方原文：沉浸光感「…其他组件仅在 Navigation/NavDestination 标题栏，或横向 Tabs 中 barPosition = BarPosition.End 的底部 TabBar 中生效」⇒ 自绘控件本来就拿不到材质。

**通用原则**：任何“阅读器内部、但可能与书架同时出现在屏幕上”的界面，
亮暗必须来自阅读器本地状态，禁止依赖系统材质或全局主题。

## 6. 血泪教训（务必遵守）

1. **禁止 `git add -A`**：曾把 `Index.ets`（书架页）从 2888 行带成 490 行进了提交；现已加护栏脚本，仍要逐文件 add + 提交后 `git show --stat` 自查。
2. **不要用 PowerShell 拼字符串改文件**：`-Value($a+$b)` 会吞换行（曾把 1698 行文件压成 1 行）；批量 `WriteAllText` 之后**先核对行数**再继续。
3. **HDS / 系统材质不要试图“单独染色”**：bar 底色、`gradientMask` 蒙层、`systemMaterial` 都由整机模式驱动；文档层面没有“按页覆盖”的入口。
4. **材质采不到 XComponent（ReaderKit `ReadPageComponent`）内容** ⇒ 仿真/横滑档永远没有真模糊；要一致的观感只能用**纯色半透明**（顶栏已证可行）。
5. **云调试可以安装主包**（2026-11-01 实测，XT2 上跑通）；探针（`tools/readerprobe`）仍然只用来量引擎参数。
6. 云机会话之间 **density 会变**（同一台 XT2 曾报 2.55 与 3.0）⇒ 跨会话只能比 px，不能比 vp。
7. 探针改 `fontSize` 对引擎**不生效**（14→28 五档 MEASURE 完全相同）；`pitch` 指标随视口漂移，不可作判据，只有 `first`（首行墨迹 px）稳定。
