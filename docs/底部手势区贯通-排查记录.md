# 书架"底部手势条那一行有横条 / 内容画不到屏幕最底"排查记录（2026-10-11）

> 结论先行：这是**两个互相独立的元凶**叠在一起，必须两个都修才算"贯通"。
> 全文所有数字都是真机实测（Mate 80 Pro Max，1320×2848 px，密度 3.25）。

## 0. 症状（用户原话）

> 「底部的手势条还是有个白条蒙版……你看看设置页，设置页底部就没有」
> 「最下面一行书在手势条那里是**被挡住**的，不是直接从屏幕到最底端；手势条这一行**是有颜色的**」

对照物：设置页（`MySetPage`）底部看起来是"贯通"的，书架不是。

## 1. 元凶一：HDS 悬浮页签自带的**背板蒙层**（灰白"横条"）

`HdsTabsFloatingStyle.gradientMask` —— **代码里不写这个字段 = 用官方默认 = 蒙层存在**。

- SDK：`…\sdk\default\hms\ets\api\@hms.hds.hdsBaseComponent.d.ets:5416`
  `gradientMask?: HdsTabsBackgroundStyle;`（注释「Sets gradient mask for bottom of tabs.」），
  其 `maskColor?: ResourceColor` / `maskHeight?: number` 见同文件 `:5015-5035`。
- 官方 API 参考「默认值」列（documentId `API参考/UI_Design_Kit_UI设计套件/ArkTS组件/HdsTabs_底部页签/ui-design-hdstabs`）原文：
  「default：蒙层颜色浅色模式是 **#CCF1F3F5**，深色模式是 **#99000000**。蒙层高度等于页签栏默认高度加 16vp。
  说明：**蒙层高度不可设置为 0**。」
- 像素验算（旧截图 `screenshot_20261010_210433/210552`）：
  - 书架最底 `(243,242,240)` ≈ `0.8×#F1F3F5 + 0.2×#ffece0` ✓
  - 设置页最底 `(243,244,246)` ≈ `0.8×#F1F3F5 + 0.2×#F5F5F5` ✓
  ⇒ **同一层蒙层，两页都有**；设置页"看不见"只是因为它的底色和蒙层色几乎同色（差 ~2 级），
  书架是主题色 `#ffece0`（差 ~14 级）。**"设置页为什么贯通"的答案 = 颜色巧合，不是结构差异。**
- 关法（唯一）：`gradientMask: { maskColor: Color.Transparent }`（官方禁止高度 0 ⇒ 只能把颜色设全透明）。
  位置：`entry/src/main/ets/pages/Index.ets` → `hdsFloatingStyle()`。

### 真机 A/B（单变量，两次构建+安装）

| 状态 | 手势条行背景 y2800-2840 | 第 6 本"preface"最暗像素 |
|---|---|---|
| 官方默认（字段不写） | `(243,240,239)` 中性灰白 ← 那条东西 | `(190,187,186)` 被洗白 |
| `maskColor: Color.Transparent` | `(253,235,223)` = 页面色 | `(151,144,139)` 正常对比 |

（页面自身底色 `(255,236,224)`。截图：`D:\tmp\devshots\ab_mask_on.png` / `ab_mask_off.png`。）

### 它是怎么回来的（迁移漏迁）

- 2026-09-28 `f100bab`：底栏改"悬浮 dock"，用 ArkUI 原生 `Tabs`，当时**显式关掉了系统遮罩**
  （`ImmersiveMaterialUtil.tabsFloatingStyle()`：`maskColor: Color.Transparent, maskHeight: 0`）。
- 2026-10-09 `fe2dd1e`：迁 HDS `HdsTabs` —— 字段改名成 `gradientMask`，且新组件**禁止 0 高度**，
  老写法搬不过来；新代码里这个字段没写 ⇒ 蒙层静默回归，**两天后才被发现**。

## 2. 元凶二：滚动容器**盒子自己的底部外边距**（内容被截在屏幕底以上）

`BookContent.ets` 的 List 曾带 `.margin({ bottom: 20 })`（2025-12-23 `d2b00b5` 首次导入时的老代码，
当时底部还是普通贴底条，留 20vp 当"让位"；`f100bab` 改成悬浮 dock 后**避让职责搬到 `contentEndOffset`，
这条老边距忘了删**）。

真机 dump 对照（`devecocli ui layout --format json`）：

| 页面 | 列表容器 bounds | 底边 |
|---|---|---|
| 书架 `BookContent` 的 List | `[50, 668 → 1270, **2781**]` | 比屏幕底（2848）少 67px ≈ 20vp |
| 设置 `MySetPage` 的 List | `[0, 293 → 1320, **2848**]` | 铺到屏幕最底 |

⇒ 最后一行书永远画不进最底下那一条（那一条只剩空白页面底色；旧版再叠元凶一 ⇒ 灰白横条）。
`contentEndOffset` **只偏移内容末尾、不动盒子**，所以删除该外边距不会让最后一本书被 dock 压住。

## 3. 定位方法（可复用，下次照这个顺序）

1. `devecocli device list` → `devecocli ui layout --format json > dump.json`
   → 找「正常页 vs 异常页」里**同一个元素**（List/Refresh/Stack…）的 `bounds` 并列对比
   —— 这一条就抓到了元凶二（2781 vs 2848）。
2. `devecocli ui screenshot` → 逐行采样颜色（同分辨率）→ 反推是哪一层：底色？蒙层？阴影？
   —— 这一条把元凶一的颜色算出来（`0.8×#F1F3F5 + 0.2×底色`）。
3. 官方文档/SDK 里找该字段的「默认值：」列 —— 确认"没写 = 有"。
4. **单变量 A/B**：只注释掉可疑的那一行 → 构建 → 安装 → 再截图对比 —— 因果落实。
   注意：`hdc install -r` 后要重新 `aa start`，否则拍到的还是旧进程画面。

⚠️ 本次踩过的误判：一度归因「`linearGradient` 0.2 之后重复着色」。**错**——
`repeating` 默认 `false`（官方 `…/视效与模糊/颜色渐变/ts-universal-attributes-gradient-color`），
实测 y=660 以下恒为第二色、无周期变化。

## 5. 通用规则（写给后来者）

1. **组件换代（ArkUI 原生 → HDS 等）时，旧代码里"显式关掉的系统默认效果"必须逐条复查**；
   字段可能改名、默认值可能变、旧参数可能被禁止（本例：`maskColor`→`gradientMask`、禁止 0 高度）。
2. **"没写这个字段" ≠ "没有这个效果"**：系统/HDS 组件默认值往往就是"有"，查 API 参考的「默认值」列。
3. **滚动容器（List / Scroll / Grid / WaterFlow）盒子自身的底部 margin/padding 会把内容截在屏幕底以上**；
   底部让位一律用 `contentEndOffset`（只动内容末尾）或给内容加内边距。
4. 判断"某一层是不是它干的"：**同一元素两页 bounds 对比 + 逐行采样 + 单变量 A/B**，三件套缺一不可。
