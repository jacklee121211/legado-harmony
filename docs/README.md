## ⚠️ 免责声明（先读这三条）

1. **本目录所有文档仅供参考，不能作为无条件信任的答案。**
   文档是**当时**的取证与结论；代码随时在变 ⇒ 可能已失效、已证伪，甚至当时就是错的。
2. **任何结论必须回到代码或真机复验才成立。** 冲突时按项目铁律判定：
   **真机实测 > 官方 SDK 声明(.d.ts) > 官方文档 > 静态检查(lint/MCP) > 本目录文档 > 直觉**。
3. **索引里的可信度标记是"最后一次核对时的状态"，不是永久保证。**
   看到 ⚠️ / ❓ / 📦 的条目，请当作"线索"而不是"结论"。

### 可信度图例

| 标记 | 含义 | 怎么用 |
|---|---|---|
| ✅ | **已实测**：有真机日志/截图/SDK 原文佐证，且与当前代码一致 | 可作判断依据，但仍建议对一眼代码 |
| ⚠️ | **可能过时**：结论对的概率高，但相关代码后来改过 | 只作线索，用前先核代码 |
| ❓ | **未验证**：当时是推测/估算，没实测 | **禁止引用**，要用先补证据 |
| 🔁 | **已推翻**：曾写进文档但后来被证伪 | 只作"别再这么想"的反例 |
| 📦 | **历史归档**：当时的方案/排查记录，方案可能已废 | 只读来理解"为什么否掉"，不要照做 |

## 二、文档规范（2026-11-05 起强制，所有 agent 必须遵守）

### 2.1 只准这 7 种文档类型（前缀即类型）

| 前缀 | 用途 | 生命周期 |
|---|---|---|
| `架构-<域>-<主题>.md` | **契约级真源**：写入口/树/事件/语义，改代码前必须服从它 | 长期，改了要立刻同步 |
| `标准-<主题>.md` | 强制规范（弹窗/按钮/文档/命名） | 长期 |
| `交接-<主题>-<日期>.md` | 一句话现状 + 剩余项 + 铁律，给下一个人/agent 接手 | 每轮更替，旧的移 `archive/` |
| `状态卡-<主题>-<日期>.md` | 进度卡：指标/剩余项/已知坑 | 同上 |
| `待办-<主题>-<日期>.md` | 施工记录：每批含**取证原文**、改动、验收、遗留 | 长期（只追加） |
| `记录-<主题>-<日期>.md` | 排查记录/验收记录（一次性的事实存档） | 归档 |
| `归档-<主题>.md` | 已废方案/已推翻结论（写明"别再照做"的原因） | 永久只读 |

**禁止**：`临时.md`、`新建文本文档.md`、名字里没有日期的一次性记录、以及**同一主题的第二份平行文档**。

### 2.2 每份文档必须有头部块（缺一条就算不合格）

```markdown
# <标题>

> **可信度**：✅已实测 / ⚠️可能过时 / ❓未验证 / 🔁已推翻 / 📦归档
> **适用范围**：<哪些代码/场景>　**最后核对**：<YYYY-MM-DD>（谁核的：agent/human）
> **依据**：<真机日志行 / SDK 文件:行 / documentId / 截图路径>
> **一句话结论**：<30 字内，让读者不点开就知道值不值得读>
```

### 2.3 三条硬规矩

1. **新增文档前必须先在 `README.md` 索引里搜主题**：已有同类 → 改旧的，不许开新的平行文档。
2. **代码改动若让某文档结论失效**：同一笔提交里改该文档的头部（可信度 + 日期），并在索引表更新。
   懒得改？→ 把该条降级成 ⚠️ 并在"最后核对"写清"代码已变，未复核"。
3. **纯推测必须写 `❓`**；被证伪的结论**不要删**，改成 `🔁` 并写"为什么错"——那是最省时间的防复发资产。

### 2.4 目录约束

- 文档一律放 `docs/`，**不许**在仓库根或 `entry/` 下新增 `.md`（除 `AGENTS.md`）；
- 图片/表格/一次性脚本放 `docs/assets/`（**待迁移**：当前 `docs/*.png|*.csv|*.py` 还没搬，见 §四）；
- 过时文档移 `docs/archive/`（**待建立**），不要直接删 —— 里面有"为什么否掉"的价值。
