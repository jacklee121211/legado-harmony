## 零、先纠正一个认知：阅读器里是**三套模型**，不是一套

| 概念 | 实际承载页 | 入口条件（证据） |
|---|---|---|
| **txt** | `ReaderPage3`（ReaderKit，仿真/横滑）或 `ReaderPageNoAnim`（自研，上下/无动画） | 翻页模式决定，见 AGENTS.md §7；`RouteName.READER` |
| **非 txt（epub/mobi/azw3/docx）** | 仍走 `ReaderPage3`，先经 `BookSourceResolver` 转成本地路径 | `ReaderPage3.ets:4691-4704`（`startPlay: 新格式 → %{public}s` / 转换失败提示） |
| **pdf** | **两套活页 + 一条死页**：`PdfViewerPage`（`FMT_PDF_USE_PDFVIEW=true`）／`ReaderPage3` 的 `isPdfBook` 缩放态（`ReaderPage3.ets:4357`、`2546-2552`）／`PdfReaderPage`（`FMT_PDF_USE_SELF_VIEWER=**false**`，旧实验） | 见 `FormatFlags.ets:66/73`、`BookInfoGrids.ets:254/273`、`BookInfos.ets:286/310`、`ReaderPage3.ets:4357` |

**由此暴露的严重问题（R1）**：**同一本 PDF，从哪儿点进去，进的阅读页不一样**

- 从**书架宫格/列表**点 → 走 `BookInfoGrids:267` / `BookInfos:305` 的判定 → `RouteName.PDF_VIEWER`（`PdfViewerPage`）
- 从**继续阅读 / 书籍详情 / 阅读统计 / 我的中心**点 → 直接 `AppRouter.push(RouteName.READER)`
  （`Index.ets:609/778`、`BookDetailPage.ets:239/298/474`、`MyCenter.ets:190`、`ReadStatsPage.ets:653`）
  → 进 `ReaderPage3`，只是把 `isPdfBook` 置 true 挂上"点图放大"

⇒ 两套 PDF 阅读体验并存，且**事实写入路径也不同**（见 R2）。

## 一、R 组：阅读器三概念收口（本次新增，用户点名）

### R1 PDF 入口判定重复两份，且与其它 6 个入口不一致
- **证据**：`BookInfoGrids.ets:254-282` 与 `BookInfos.ets:286-318` 是**同构的两段判定**
  （`FMT_MASTER_ENABLED && FMT_PDF_ENABLED && FMT_PDF_USE_PDFVIEW && isPdfPath(...)` →
  `push(PDF_VIEWER)`；否则 `FMT_PDF_USE_SELF_VIEWER` → `router.pushUrl(PdfReaderPage)`）。
  另 6 处 `push(RouteName.READER)` 完全没有这个判定。
- **修法**：新增 `common/reader/ReaderEntry.ets`（或 `ReaderLane`）：
  `open(book, ctx)` 单点决定「txt/非txt → READER；pdf → PDF_VIEWER」，全部 9 个入口改调它。
- **验收**：9 处入口改为 1 处实现；同一 PDF 从书架/详情/继续阅读/统计进入**页面一致**。
- **风险**：中（涉及 6 个文件的跳转；一镜到底 `longTakeTransitionParam` 传参不能丢）。

### R2 `PdfReaderPage` 仍在直写 books 事实，且不在闸门 scope 内
- **证据**：`PdfReaderPage.ets:145` `BooksDao.partialUpdate(this.book)`；
  闸门 scope 只有 `(ReaderPage3|PdfViewerPage|ReaderPageNoAnim|ReadPageComponent)`（`scripts/check-single-path.mjs`）。
- **修法（二选一，建议前者）**：
  ① **删除该页**（`FMT_PDF_USE_SELF_VIEWER=false` 已是死路；连带删 2 处 `router.pushUrl` 回退分支）；
  ② 若保留，改走 `ReaderPorts.saveProgress/settleOnExit`。
- **验收**：`reader-fact-write` 闸门 scope 扩到 `Reader` 目录**全部** `.ets`，仍为 0；页数减少。
- **风险**：低（死代码）；删页要同步删 `ProbeAbility`（`PdfProbePage` 是探针页，另议）。

### R3 `ReaderPage3` 的 pdf 分支与 `PdfViewerPage` 功能重叠
- **证据**：`ReaderPage3.ets:4357`（isPdfBook）、`2546-2552`（`isPdfZoomed`）、`8434/8459/8499/8547`（缩放态布局）。
- **修法**：明确"pdf 只由 `PdfViewerPage` 承担"后，把 `ReaderPage3` 里的 pdf 缩放分支标 `@deprecated`
  或直接删除（需先确认 R1 后不再有 pdf 进 ReaderPage3）。
- **验收**：pdf 从任一入口都进 `PdfViewerPage`；`ReaderPage3` 无 `isPdfBook` 分支。
- **风险**：中（删分支可能连带 `PDF_ZOOM_ACTIVE` 清理逻辑，须一并处理，见 `4358-4366` 注释里的坑）。

### R4 三个阅读页 + 探针页的归属要写清
- 现状文件：`ReaderPage3`（主）、`ReaderPageNoAnim`（自研无动画）、`PdfViewerPage`（pdf 活页）、
  `PdfReaderPage`（pdf 死页）、`PdfProbePage`+`ProbeAbility`（探针）。
- **修法**：R2/R3 之后只剩 3 个活页，把"哪个格式 × 哪种翻页模式 → 哪个页"写进 `docs/` 与代码头注释，
  并在 `ReaderEntry` 里用**表**表达，禁止再散落判断。
- **验收**：文档与代码一致；新增格式只需改 `ReaderEntry` 一处。

## 十二、P4 记录：阅读页返回键（A2）—— 探针 → 定位 → 兜底

### 12.1 探针（临时，任务结束已删）

在三处埋 `[BACK]` 日志：`Index.onBackPress()`（@Entry 页级）、两个 `NavDestination.onBackPressed`
（READER 飞行分支 / 普通分支）、`ReaderPage3.aboutToDisappear()`。

### 12.2 真机结果（5 次试验：点书后 40 / 80 / 150 / 250 / 600ms 按返回）

每一次都是同一对日志：

```
I A03D00/com.jk.reader/JSAPP: [BACK] dest.onBackPressed zoom=false
I A03D00/com.jk.reader/JSAPP: [BACK] ReaderPage3.aboutToDisappear
```

- **`page.onBackPress` 一次都没出现** ⇒ 正常路径由 `NavDestination.onBackPressed` 消费，页面级根本收不到；
- 5 次都正常回到书架、进程存活（`pidof com.jk.reader` 不变）；
- ⇒ 用户报的"偶发退回桌面"**在本轮无法复现**（与"A2 第 11/14/15/18 轮各 1 次"的偶发特征一致）。

### 12.3 修法（按证据，不改正常路径）

`@Entry` 页（`Index`）在这一层的默认行为就是**退出应用**。只要有哪一帧 Navigation 没接住返回
（转场中 / 容器重建 / 栈未就绪），事件就会落到 `Index.onBackPress()` 的 `return false` ⇒ App 直接没了。

所以只加**兜底**，不动正常路径：

```ts
onBackPress(): boolean {
  const top = AppRouter.topName();
  if (top === RouteName.READER || top === RouteName.PDF_VIEWER) {
    if (PDF_ZOOM_ACTIVE) { return true }         // PDF 放大态：静默吞（原逻辑）
    console.warn('[BACK] page-level fallthrough: top=' + top + ' → 自己 pop 并消费');
    AppRouter.pop();
    return true;                                  // 绝不把返回漏给系统
  }
  return false                                    // 书架根页：保持系统默认（退出/后台）
}
```

- 正常路径**不会**走到这里（探针已证）；走到了才打 warn 并自行弹栈 ⇒ 把"退出 App"变成"回书架"；
- 书架根页仍是 `return false` ⇒ **返回键在书架照旧退出**（已真机确认）。

|---|---|

## 十三、P5 记录：A3 弹窗热区 / A4 标题三态 / A5 分组封面恢复默认

### 13.1 A3 —— 「移动至/分组管理」行内左侧点不动

**根因（代码级）**：`groupRow()` 里整行结构是
`Row{ Row(width=depth*14) 缩进 · Row(width=16) 图标占位 · Row(layoutWeight=1){icon+名称}.onClick(...) · Row(width=36) 箭头.onClick }`
—— **可点的是中间那段**，左侧缩进与 16vp 占位在它外面。深层分组 `depth*14` 可达 42vp+，
真机上点 (372,1479) 落在缩进里 ⇒ 无反应；(700,1479) 落在名称里 ⇒ 出确认。

**修法**：把那段内联闭包原样抽成 `onRowTap(row)`，`.onClick` 抬到**整行**（外层 Row）：
- 缩进 / 图标 / 名称 / 路径 全部响应；
- 行尾 36vp 箭头是**子节点且自带 onClick**，按 ArkUI 命中规则优先消费 ⇒ "点箭头=展开/收起" 不被父级吞掉。

### 33.1 取证：`StoreConfig` 里**没有** version/onUpgrade（推翻了原计划前提）

| 来源 | 结论 |
