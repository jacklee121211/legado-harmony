## 0. 一句话现状

**两套排版引擎并行**（这是现状，不是缺陷）：

| 档位 | 引擎 | 实现 |
|---|---|---|
| 仿真 / 横滑 | **ReaderKit `ReadPageComponent`**（内嵌 **Chromium**） | 官方组件，不可改内部 |
| 上下 / 无动画 | **自研**（`@ohos.graphics.text` / **ArkGraphics 2D**） | 我们的 `EngineLines` |

**已把自绘两档与 ReaderKit 的版式参数逐像素对齐**（见 §2），但**两个引擎的断行差 ±1 字是物理极限，无法消除**。

**下一步方向：用官方 API 自研横滑 + 仿真，逐步取代 ReaderKit 的渲染层**（见 §5）。

## 2. 自绘两档与 ReaderKit 的版式对齐（已完成，勿破坏）

五个参数，全部有真机像素实测依据（同一章连续 5 页 × 两模式逐行比对）：

| 参数 | 位置 | 值 | 依据 |
|---|---|---|---|
| **正文字距** | `EngineLines.ets` `LETTER_SPACING_FP` | **1.7fp** | ReaderKit 86.2px/字 vs 我们 80.4px/字 ⇒ 它多约 5.8px 字距 |
| **行高** | `ReaderPage3.ets` `scrollLineHeightFp()` | `lineHeight × fontSize`（**不乘系数**） | 去掉 `effectiveLineMul()` 后 154px 与 ReaderKit 一致 |
| **段间距** | `ReaderScrollView.ets` `SCROLL_PARA_GAP_EM` | **0.95em** | ReaderKit 实测约 93px（我们 77px），当前靠 inset 补偿，**见 §7 残留问题** |
| **章标题** | `EngineLines.ets` `TITLE_FONT_SCALE` / `TITLE_FONT_WEIGHT` | **1.33 / 600** | 标题宽 775px vs ReaderKit 776px |
| **上下 inset** | `ReaderPage3.ets` `SELF_DRAWN_TOP_TRIM_VP=10` / `SELF_DRAWN_BOTTOM_PAD_VP=30` | 减 10vp / 加 30vp | 标题顶部 385px vs ReaderKit 384px；消除第 3 页起「每页多装 1 行」 |

**验证结果**：第 1/2 页末行差 0~3px；第 3 页内容一致；11 个行位置最大偏差 1px。

### 排版架构

```
buildChapterNodes(content)            ← 段落模型（与 ReaderKit 块节点 1:1 映射）
    ↓
EngineLines.buildEngineLines()        ← 引擎排行：@ohos.graphics.text 的 layoutSync + getLineMetrics
    ↓                                产出 EngineLine{text, paraIndex, charFrom, charTo, heightPx, isTitle, padTopPx}
    ├─ 无动画：paginateLines() 按页高精确切页 → ReaderPageNoAnim（每行一个 Text）
    └─ 上下：直接按行渲染 → ReaderScrollView（每行一个 Text，List + LazyForEach）
```

**核心文件**：`entry/src/main/ets/pages/view/Reader/EngineLines.ets`（唯一排版权威）

## 3. 已废弃 / 被否决的方案（❗ 别再走）

| 方案 | 结论 | 原因 |
|---|---|---|
| **移植基座 `readerLibrary` 的横滑/仿真** | ❌ **用户实测否决：效果极差** | 基座用「逐列 `drawImage` 拼条带」模拟卷曲 ⇒ 接缝/断裂/无透视；横滑只有硬平移无阻尼。详见 `docs/最终方案-横滑仿真移植.md`（已废弃） |
| **基座本身用的也是 ReaderKit** | 事实 | 基座 `ReaderPage3.ets` → `ReadPageComponent`；`readerLibrary` 是**无外部路由的废弃模块** |
| 自绘两档混用"沉浸听读层" | ❌ 已删开关 | 听书统一锁死无动画，高亮走 `Span`，沉浸层恒不激活 |
| `effectiveLineMul()` 行高系数 | ❌ 已弃用 | 旧架构「用 ReaderKit 每页行数反推行高」的产物，把行距撑大 25% |
| `ReaderKit` 的 `hlBands` 栅格高亮 | ❌ 不再使用 | 观感差；听书永远走无动画档的自绘 Span |

## 4. 关键技术坑（全部真机踩过，勿重犯）

### 4.1 `StrutStyle` 只给 `height` 完全不生效

```ts
// ❌ 实测 m.height 只返回字体自然高度（32px 字 → 95px），配置的 193.61px 被忽略
{ fontSize: 32, height: 6.05 }

// ✅ 必须三件套
{ fontSize: 32, height: 6.05, enabled: true, heightOverride: true, forceHeight: true }
// → 194px ≈ 配置 193.61px
```

证据：`@ohos.graphics.text.d.ts` 的 `StrutStyle` 有 `enabled` / `heightOverride` / `forceHeight` / `halfLeading` / `leading` 五个可选字段。

### 4.2 分页必须用引擎实测行高，不能用配置值

`LineMetrics.height` 才是真行高；用 `lineHeightPx` 累加会多塞一行 ⇒ **最后一行溢出到 dock 下方**。

### 4.3 ArkTS 禁用索引访问类型

```ts
const fl: GestureEvent["fingerList"] = e.fingerList;   // ❌ arkts-no-aliases-by-index
const fl = e.fingerList;                                // ✅ 靠推断
```

### 4.4 `Stack` 层序会吃掉子组件手势

`ReaderPageNoAnim` 的 `Stack` 从下到上：① 背景 → ② 正文 Column（每行 Text）→ ③ 触摸分区 Row。
**③ 在最上层且各分区都挂了 `onClick` ⇒ ② 里的任何手势都收不到。**
⇒ 长按气泡必须挂在 **③** 上，用落点 `localY` 逐行累加反算命中行（见 `onBodyLongPress()`）。

### 4.5 `rangeCovers` + `char = 0` = 逐页翻页 60 页

书签 / 章节跳转的 `char` 恒为 0，而 `rangeCovers` 要求 `(node, char)` 落在 `[startNode#startChar, endNode#endChar]` 内。
当目标段是「页首的续段」（`startChar > 0`）⇒ `startChar <= 0` 为假 ⇒ 判成未落位 ⇒ 走 `beginSearch` **逐页逼近（上限 60 页）**。
**修法**：`locateHit()` —— `char <= 0` 时只按段号判定；且书签入口必须 `noFallback = true`。

### 4.6 `applySelfDrawnPos` 的 `startChar` 曾写死 0

导致「从本页开始读」在页首是半段时**跳到上一页**。已修：`reportAt()` 上报页首行 `charFrom`。

### 4.7 `indexOfNode` 只按段号定位会落到「该段起始页」

页首半段时会退到上一页。已修：加 `char` 参数，找「包含该字符」的页。

### 4.8 切档会被误判成「用户手动翻走」

`applySelfDrawnPos` 里 `navRecently = Date.now() - lastNavMs < 1500`，切档不经过 `requestLocate` ⇒ `lastNavMs` 是旧值 ⇒ `followSuspended = true` ⇒ **自动翻页永久停摆**。
已修：`rearmListenFollow()` 在切档后清除挂起 + 刷新 `lastNavMs`。

### 4.9 改 PowerShell 字符串会吞特殊字符

`"$a`r`n$b"` 里的 `` `r ``/`` `b ``/`` `e `` 会被当转义符 ⇒ 注释里的 `reportAt` 变 `eportAt`、`buildChapterNodes` 变 `uildChapterNodes`。
**改 .ets 一律用 `edit` 工具**，不要用 PowerShell 拼多行字符串。

## 5. 新方向：用官方 API 自研横滑 + 仿真（待开工）

### 5.1 技术依据（已查证，全部在 API 20 兼容线内）

```ts
// @ohos.graphics.drawing.d.ts:2121
/**
 * Draws a PixelMap based on a mesh, with the mesh vertices evenly distributed across the PixelMap.
 * @param { Array<number> } vertices - Array of vertices; size must be ((meshWidth+1)*(meshHeight+1)+vertOffset)*2
 * @param { Array<number> | null } colors - Array of colors at each vertex. [since 20]
 * @since 12
 */
drawPixelMapMesh(pixelmap, meshWidth, meshHeight, vertices, vertOffset, colors, colorOffset): void;
```

**这就是 mesh warp（网格变形），是仿真卷曲的正确底层** —— 一次性绘制整张变形图，**没有基座「拼条带」的接缝问题**；`colors` 顶点色可做卷曲处的阴影/高光衰减。

**能力栈完整**：
- 排版 → `@ohos.graphics.text`（已有 `EngineLines`）
- 页面转位图 → `componentSnapshot.getSync`（实测全屏 42~117ms，**每次翻页只截 1 次**）
- 变形绘制 → `drawPixelMapMesh`
- 手势/动画 → `PanGesture` + `animateTo`

**⚠️ `drawVertices` 是 `@since 23`，超出兼容线，不能用**（但 `drawPixelMapMesh` 够用）。

### 5.2 分两步走

**第一步：横滑（2~3 天，低风险）**

新建 `ReaderSlideView.ets`，**不动现有任何档位**，用开关切换，不满意直接删。

目标（重点在**手感**，不是平移）：
```
PanGesture 跟手 → translate 当前页
边缘阻尼（第一页/最后一页往回带 0.3 倍位移）
松手：|offsetX| > 30% 屏宽 或 fling 速度 > 阈值 → animateTo 翻页；否则回弹
预加载当前 ±1 页，翻页瞬间不能白屏
```

**第二步：仿真（5~8 天，看第一步结果再定）**

```
① 页面 → PixelMap（componentSnapshot.getSync，每次翻页 1 次）
② 贝塞尔卷曲 → 顶点网格映射（meshWidth × meshHeight，建议 20×30）
③ drawPixelMapMesh 一次性绘制
④ colors 顶点色做阴影衰减 + 高光
⑤ 背面页镜像渲染
```

### 5.3 效果上限（**开工前必须认清，别以为能做到 100 分**）

`@ohos.graphics.drawing` 里**没有 shader / RuntimeEffect / 实时光照**（检索 `Shader|RuntimeEffect|Lighting` 只命中 `FilterMode` / `MaskFilter` / `Brush` 三种基础能力）。
`drawPixelMapMesh` 给的是「任意顶点位置 + 网格内纹理插值 + 顶点色」，**没有法线、没有光照模型**。

**✅ 能做，而且能做好（约 90% 的观感）**

| 效果 | 手段 |
|---|---|
| 卷曲几何形状 | 网格够密就精确（20×30 已平滑，40×60 基本看不出多边形） |
| 卷曲处明暗渐变 | `colors` 顶点色按曲率**预先算好** |
| 页面透视 / 倾斜 | 顶点位置直接算投影 |
| 背面内容 | 第二张**镜像位图**，分两次绘制 |
| 翻页投影（页在背景的阴影） | 外层 `Stack` 的 `shadow` + `blur`，与 mesh 无关 |

**⚠️ 做不到 / 只能糊（这 10% 最容易被眼睛抓到）**

| 效果 | 原因 |
|---|---|
| 纸张半透明 + 背后文字透光 | 一次只画一张不透明位图；叠加成本与瑕疵都高 |
| 卷曲边缘的锐利高光（纸面反光的亮线） | 无光照模型，顶点色只能做平滑渐变 |
| 法线随曲率实时变化 | 明暗是预烘的顶点色，曲率一变要整组重算（每帧 CPU） |
| 多层折痕 / 揉皱 | 需多次 mesh 叠加，混合模式有限，易糊 |

**量化判断**

```
几何形状 100% ｜ 明暗渐变 90%（无锐利高光）｜ 背面 95% ｜ 纸张质感 40%（只能贴图假装）｜ 物理惯性 100%（与卷曲无关）
```

**⇒ 能做到「一眼看上去像真纸在翻」，但快速翻、凑近看时缺「光在纸上流动」的细腻感。**
**参考基线：基座（拼条带）= 约 20 分；`drawPixelMapMesh` = 约 80~85 分，是质变。**

**【推测】iBooks / 掌阅那类「高级感」很大比例来自纸张贴图 + 美术调校的阴影曲线，而非算法本身** —— 未取得其实现证据。

**要做 95 分的唯一路径**（仅在实测后确认「就差那口气」才值得投）：
```
XComponent(type:'surface') → OHNativeWindow → OpenGL ES 3.0 → 自定义 fragment shader
```
逐像素物理模拟（曲率→法线→光照→采样全在 shader）可行，但代价：C++ + EGL/GLES 管线、页面须先渲成纹理、**2~4 周**、shader 出错表现为黑屏无报错、与 ArkUI 布局/手势要手工桥接。

### 5.4 终局形态（用户已认可）

```
解析：ReaderKit.bookParser（**必须保留**，epub/azw/mobi 解析不可能自写）
排版 + 渲染 + 翻页：全自研（ArkGraphics 2D）
```

**注意**：自研完成后 `ReadPageComponent` 可以彻底删掉，但 `bookParser` 一定要留。

## 6. 听书体系（刚重构完，状态稳定）

- **四档听书一律锁死无动画**：`switchReadMode` 拦截并提示「听书模式固定使用无动画，关闭听书后会自动切回」；退出听书自动还原原档
- **高亮**：自绘 `Span.textBackgroundStyle`；沉浸层恒 `false`（开关已删）
- **长按正文任意行 → 「从此处听书」气泡** → `TtsEngine.seekToChapter(spine, paraIndex, 0)`
  - 气泡挂在触摸分区层（见 §4.4），用落点 y 逐行累加反算命中行
  - `offset: { x: 0, y: 34 }`，`enableArrow: false`
- **迷你条字幕** = 当前**章节名** + `marqueeOptions`（`@since 18`）：放得下静态、放不下缓慢循环滚动
- **自动翻页**：`autoFollowTts()` → `requestLocate(朗读段)`
