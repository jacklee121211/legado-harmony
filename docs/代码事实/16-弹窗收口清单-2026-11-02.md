### 1.1 两种打开语义（改之前必须分清，否则会出"父窗被误关"的回归）

| API | 语义 | 用在哪 |
|---|---|---|
| `DialogHost.open / openIf` | **父先真关**（S7）；顺带清空 nested 子弹窗 | 页面级打开；「信息弹窗 → 子窗」这类明确的父子替换 |
| `DialogHost.openNested / closeNested` | **叠在父窗之上、父窗保持存活** | ① 分组管理 → 长按分组 → 三/四按钮确认框（原注释：「叠在分组管理之上」「分组管理弹窗本身不动」）；② 移动至 → 新建分组（连续创建；父窗关了 `@CustomDialog` 的 `@State` 实例就没了，新建的分组再也刷不回列表）；③ 封面弹窗 → 冲突提醒 |

> 本轮实测到的**回归**：`BookSelectGroupDialog` 的「隐藏分组四按钮窗」原来走 `DialogHost.open`
> （会把分组管理弹窗连带关掉），与注释声明的"叠开"语义相反 ⇒ B1b 已改为 `openNested`。

## 3. 每批的固定流程（不许跳步）

1. **改**：`<ctrl>?.open()` → `DialogHost.openIf(<ctrl>)`；`<ctrl>.open()` → `DialogHost.open(<ctrl>)`；补 import。
2. `node scripts/check-dialog-usage.mjs` ⇒ 违规数必须**下降**，且新出现的违规必须是 0。
3. `deveco MCP check`（绝对路径）⇒ 无**新增**诊断。
4. `devecocli build --modules entry` ⇒ `BUILD SUCCESSFUL`。
5. **装真机 + 冒烟**：本批涉及的弹窗逐个点开截图（见 §4 清单），并对比"改前/改后"截图无差异。
6. 提交（首行不带版本号 = 内部检查点），备注写清批次与闸门前后数字。
7. 更新本文 §1 状态表与真源文档。

### 风险点（B1b 起必须逐处判断）
`DialogHost.open()` 会**先真关上一个弹窗**（`DialogHost.ets:22-31`）。所以：
- 页面级打开（长按/点击）⇒ 无父窗，直接换 ✅
- **弹窗内打开子弹窗** ⇒ 正是 S7「父先真关、子退重建父」，属于**预期行为**，但要确认父窗关掉后回来时
  会**重新 new**（`reopen()` / 调用方已有 rebuild 逻辑），否则会出现"回来是空白/旧数据"。
