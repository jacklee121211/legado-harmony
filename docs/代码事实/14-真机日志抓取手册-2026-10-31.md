# 真机日志抓取手册（网络设备 hdc 场景，2026-10-31 实测）

适用：设备通过 **hdc 网络连接**（如 `192.168.3.241:43125`），不是 USB 直连/设备名。
本文全部命令都在本机 PowerShell 中实测可用。

---

## 0. 先说结论：`devecocli log --follow` 不要用

在**网络连接**的设备上它就卡在 `Preparing log request…`（复现 2 次）。
【推测】它内部按 USB/设备名路径找日志流，网络 hdc 下拿不到流句柄；未做源码级验证。

**替代方案（本手册的全部内容）：直接 `hdc shell hilog`。**
需要一个"持续跟随"的日志，用**持久终端**跑（见 §4），不要用 `--follow`。

---

## 1. 连接与健康检查（每次开工第一步）

```powershell
hdc list targets                                   # 空 => 断了
hdc tconn 192.168.3.241:43125                      # 重连（不需要重插线）
hdc list targets                                   # 应出现 192.168.3.241:43125
hdc shell "pidof com.jk.reader"                    # 应用在跑吗？记下 PID
```

⚠️ **PID 必须记下**：`hilog` 每行都带 PID；读到旧 PID 的日志 = 读到**上一个进程**的现象，
本工程踩过一次，白查一轮。

---

## 2. 标准抓取流程（一次"操作—抓取"闭环）

```powershell
# ① 清缓冲（关键：不清就会被上一轮的旧日志淹没）
hdc shell hilog -r

# ② 触发操作（示例：强制重启应用）
hdc shell "aa force-stop com.jk.reader"
Start-Sleep -Seconds 2
hdc shell "aa start -a EntryAbility -b com.jk.reader"
Start-Sleep -Seconds 8

# ③ 抓取：用 -T 白名单**只留自己的 tag**，比 -x 全量快一个数量级
hdc shell "hilog -x -T fliprender,NativeFlipView,NoAnimReader,testTag > /data/local/tmp/a.log"

# ④ 拉回本机，用本地 grep（比在设备上 grep 快很多，也便于统计）
hdc file recv /data/local/tmp/a.log D:\Arkts\3.8.11\_dsh_shots\verify\a.log
```

> `-T` 支持逗号分隔多个 tag，等价于你要抓的那几个模块；
> 你最后用 `hilog -x -T testTag,NoAnimReader,EngineLines` 抓到 636 行，用的就是这个思路，是对的。

### 只想看几条时（不落地文件）

```powershell
hdc shell "hilog -x -T fliprender | grep -E 'upload slot|render spec' | head -8"
hdc shell "hilog -x -T NativeFlipView | grep -c 'commit-fwd'"     # 只要计数
```

## 3. 你踩的四个坑 + 解法

| 坑 | 现象 | 解法 |
|---|---|---|
| `devecocli log --follow` 卡住 | `Preparing log request…` 不返回 | 不用它；改 `hdc shell hilog`（§1/§2） |
| `-x` 全量 dump 慢 | 16M 缓冲时几十秒 | ① 先 `hilog -r` 清空 ② 用 `-T` 白名单 ③ 只在需要时临时放大缓冲 `hilog -G 16M`，抓完 `hilog -G 512K` 还原 |
| `-P` 与 `-x` 不能组合 | 参数被拒/无输出 | 二选一：要么 `-x`（全量+过滤），要么 `-P`（分页 dump，配合 `-T`）。不要叠加 |
| `-e "locate"` 误命中 | 系统日志里的 `allocated` 也中 | ① 用 `grep -E 'locate\b'` 加词边界 ② 更好：`-T` 先按 tag 收窄，再 grep ③ 用 `grep -F` 精确串只有在需要全字匹配时才有用，不能解决 `allocated` 问题 |

## 4. 要"持续跟随"怎么办（替掉 --follow）

开一个**持久终端**，进去后直接跑 hilog（不退出就不会断流）：

```powershell
hdc shell
# 进去之后：
hilog -T fliprender,NativeFlipView,NoAnimReader
# Ctrl+C 结束，exit 退出
```

或者后台跑并落文件，然后随时读文件末尾：

```powershell
Start-Job { hdc shell "hilog -T fliprender,NativeFlipView > /data/local/tmp/live.log" }
# ……操作……
hdc shell "tail -50 /data/local/tmp/live.log"
```

## 5. 本工程额外踩过的坑（与你那边独立的经验）

1. **`grep` 里带中文会失败**：`hilog -x | grep '正在排版'` 会报
   `bad regex`（编码/引号被 hdc shell 吃掉）。**只用 ASCII 模式**匹配。
2. **探针自己会污染日志**：曾有一条探针每 30 帧打一条，864 行把环形缓冲冲爆，
   连 `gl ready` 都被挤掉 ⇒ 误判"GL 没初始化"。对策：探针限次（前 N 条）而不是限频。
3. **版本/二进制身份要核对**：安装可能被静默拒绝
   （`error: install version downgrade. code:9568263`，但 hvigor 仍打 `AppMod finish`）。
   装完必看一行：`hdc shell "hilog -x | grep 'BUILD '"`，确认跑的是新编译产物。
4. **`uitest drag` 时长 <300ms 常不被识别**：回归脚本统一用 **350~400ms**，
   否则会出现"前翻 0 次提交"的假 bug。
5. **`snapshot_display` 有 0.5~1s 延迟**：抓首帧要用"定时连拍"，
   并用 **JPEG 字节数**判断画面：纯纸色空屏约 **64KB**，正常正文页 **250~530KB**。
6. **设备会掉线**：长跑脚本里每几十条命令补一次 `hdc tconn`，或失败重试。

## 6. 可直接复用的抓取脚本（PowerShell）

```powershell
function Cap-Log([string]$tags, [string]$out) {
    hdc shell hilog -r | Out-Null
    # ... 这里放你的操作（uitest / aa start / click）...
    hdc shell "hilog -x -T $tags > /data/local/tmp/cap.log"
    hdc file recv /data/local/tmp/cap.log $out
    Write-Output ("captured lines: " + (Get-Content $out).Count)
}
# 用法
Cap-Log "fliprender,NativeFlipView,NoAnimReader,testTag" "D:\Arkts\3.8.11\_dsh_shots\verify\run1.log"
```

## 7. 常用 tag 对照表（本工程）

| tag | 内容 |
|---|---|
| `fliprender` | 原生渲染器：`surface created` / `gl ready` / `render spec` / `upload slot` / `prewarm` / `frame stats` |
| `NativeFlipView` | 槽位与手势：`slot N <- flat` / `bind[...]` / `SLIDE-END` / `GUARD` / `LIFECYCLE` |
| `NoAnimReader` | 读章与排版：`OPENSPLIT`（读章耗时）/ `BUILDFLAT` / `GAP PROBE` |
| `testTag` | 业务关键行：`switchReadMode` / `PROBE open` / `CONTINUE-COLORS` / `COLORPROBE` |
| `EngineLines` | 自研排版引擎 |
