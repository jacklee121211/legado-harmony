**B1. 书籍域 5 处 `booksDao.updateBookGroup` 直写**（闸门 `books-dao-write 5/5`）
- 机制：`FolderInfoDialog` 的移书/解散回滚直接在 UI 层写 `books.bookGroup`，与分组域的 `GroupMutation` 不对称。
- 证据：闸门输出 `5  UI 层直写 bookGroup（书籍域的"写入口"缺口）[预算 5]`。
- 修法：新建 `BooksMutation.moveTo(groupId, bookIds)` 收口，闸门 5→0。
- 代价：≈1 个文件 + 5 处替换 + 真机抽验；风险低（语义不变，只是搬家）。

### C. 真机发现的行为/手感问题

**C1. 阅读页按物理返回键**会**直接退出 App**（退回桌面/抖音），而不是回书架。
- 出现轮次：第 11、14、15、18 轮各 1 次（每次都用 `aa start` 拉回）。
- 代码现状：阅读页**没有** `onBackPress` 实现；`ReaderPage3:596` 注释记载
  「曾试过 `onBackPressed` 拦截，会让黑屏时连手势返回都没了，**已撤回**」。
- 结论：**根因未定位**（不能只凭现象断言）→ 如果要修，第一步是加 `[BACK]` 探针记录谁消费了返回键。
- 代价：探针 5 分钟；真修取决于探针结果。

**C2. 「移动分组 / 移动至」弹窗点行标签可能无反应**
- 机制：`groupRow()` 的 `onClick` 挂在**行内 `Row.layoutWeight(1)`** 上（`BookSelectGroupDialog.ets:441`），
  而行首还有 `row.depth*14` 缩进占位 + 16vp 展开箭头位（`:412-414`）⇒ **缩进区与图标不响应点击**。
- 真机证据：点标签 `(372,1479)` 无反应；点行体 `(700,1479)` 弹出「确定移动分组至DD吗？」（第 18 轮）。
- 修法：把 `onClick` 提到整行（`Row` 根）或给缩进/图标加 `.hitTestBehavior(HitTestMode.None)`。
- 代价：≈5 行；风险中（要确认不会抢掉行尾展开箭头的热区）。

**C3. 书籍长按「移动至」→ 弹窗标题写「移动分组」**
- 证据：`442-move-dialog.json` 实测文本 `移动分组`；发现 ⑤ 最早在第 2 轮记录。
- 修法：标题按 `isMoveGroupNode` 分支取「移动书籍」/「移动分组」。代价≈3 行。

**C4. 分组封面「恢复默认」没有入口**
- 证据：`coverInfoDialog.ets:198 Text('重置')` 与 `CoverStyleDialog.ets:215 Text('重置')` 都是**书籍封面**的重置；
  `coverInfoImageShow.ets:62 Text('默认样式')` 只改样式、不清 `coverUrl`。
- 修法：封面弹窗加一项「恢复默认（清除自定义封面）」，走 `GroupMutation.setGroupCover(id, '')`。代价≈15 行 + 真机验。
