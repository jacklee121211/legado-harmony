## 4. 真机操作纪律（全部用 `scripts/reader-ui.mjs`，别再手写）

```powershell
node scripts/reader-ui.mjs dump            # 列当前可点节点 + 中心坐标
node scripts/reader-ui.mjs tap 设置         # 自动：dump → 找节点 → 点中心
node scripts/reader-ui.mjs bounds 背景模糊   # 只看坐标
node scripts/reader-ui.mjs diff a.json b.json
```

**四条铁律**（每条都是踩出来的）：

1. **点之前先 dump**：面板高度随内容变化，同一控件两次 dump 能差 40~60px；dock 的「夜间/日间」按钮**文案与位置都会变**。
2. **点之后要确认**：用 `hilog`（`switchReadMode` / `readMode loaded` / 引擎 `setConfig`）或再 dump（`checked` / `backgroundColor`）。
   "点了没报错"**不等于**生效 —— 已经因此误判 3 次。
3. **色格/按钮点中心**：用 `bounds` 算 `((x1+x2)/2,(y1+y2)/2)`，不要用"上轮坐标 + 偏移"。
4. **有"点完面板自动关闭"的副作用时，下一次点击必须重新 dump**（2026-11-04 实测）：点「阅读方式」的
   任一档后设置面板立即收起，紧接着按旧坐标点第二下会落到 dock 的「听书」上（开出朗读面板、日志为空，
   差点误判成"切换失败"）。**连点两下是禁止动作**。
5. **「无动画」档点屏幕中间不出工具栏**（2026-11-04 实测）：分页两档点中间能唤出 dock，但自绘层
   （上下/无动画）**点中间没反应**，要点**屏幕下部**（如 `660,2500`）dock 才出现，再点「设置」。
   排查时先 `devecocli ui screenshot` 看一眼 —— dump 只有文本节点，看不出 dock 是否真的在。

**⚠️ hdc 版本坑（2026-11-04 实测，必须先解决否则一切真机验证都做不了）**：
PATH 上的 `hdc` 是 `1.2.0a`（`…\Huawei\Sdk\openharmony\9\toolchains\hdc.exe`），设备会拒：
`list targets` 能通但 `shell` 一律 `[Fail][E000001]:The sdk hdc.exe version is too low`。
**必须把 DevEco SDK 的 toolchains 前置到 PATH**（`Ver: 3.2.0f`），并先 `hdc kill` 掉残留旧 server：

```powershell
$env:PATH = "D:\Program Files\Huawei\DevEco Studio\sdk\default\openharmony\toolchains;$env:PATH"
hdc kill; hdc tconn 192.168.3.241:43125      # → Connect OK
hdc -t 192.168.3.241:43125 shell "echo hi"   # → hi
```

（`scripts/reader-ui.mjs` 内部直接调 `hdc`，所以也要在同一 PATH 下运行。）

## 6. 这段重构里最容易犯的四个错（都已发生并修正过）

| 错 | 症状 | 正确做法 |
|---|---|---|
| 真源方向写反 | 用户保存的设置每次进书被默认值顶掉 | 装载期 = 来源→模型；运行期 = 模型→快照 |
| 模型实例直接落盘 | 持久位出现 `__ob_` 脏键（历史事故） | 一律经 `snapshot()` / `toReadSettingRecord()` |
| 页面套 `@State` 持模型 | 编译报错（V1 不能装饰 V2 class） | 普通成员 |
| 用正则检查代码 | `\s` 含换行 / `String.raw` 里 `\t` 不是制表符 / `===` 被当赋值 | 逐行解析，正则只用行内小片段 |
