# TTS 停顿拼接算法：等价性验证

## 这是什么

`entry/src/main/ets/tts/PauseSplicer.ets` 是听书链路的**纯算法核心**（标点停顿识别 → PCM 静音拼接 → 时间轴映射）。它直接决定：

- 朗读到标点时停顿多久
- 播放进度与高亮/锁屏歌词是否对齐
- 块与块之间有没有咔哒爆音

2026-10-25 为消除与 ColorTxt（MPL-2.0）的代码重合，对其中 4 个函数做了**纯实现层重写**（对外契约、输入输出、数值行为均不变）：

| 函数 | 重写方式 | 原重合率 → 现 |
|---|---|---|
| `collectPauseRuns` | 逐字符游标状态机 → 单条全局正则一次性切簇 | 100% → 15.4%（仅剩函数签名行） |
| `alignWords` | `for` + `continue` + 外部游标 → `reduce` 折叠累加器 | 36% → **0%** |
| `mergeRanges` | 取末元素原地改写 → `reduce` 返回新数组 | 21% → **0%** |
| `scaledPauseMs` | 短路表达式 → 分步守卫 + 显式封顶 | 50% → **0%** |

文件级重合率：**20.8% → 7.3%**（剩余为 `for (let k = 0; k < n; k++) {` 这类唯一写法骨架）。

## 为什么必须验证

这些函数**改错不会报错**——编译通过、逻辑自洽，但听感/对齐会悄悄劣化：

- 停顿点少识别一个 → 该停的地方不停
- 时间轴映射偏移 → 高亮比语音快半句
- 淡入淡出边界错位 → 块间咔哒声回归

而 TTS 播放链路**无法在本地用肉眼验证**（要真机 + 真实音频 + 人耳）。所以必须用**新旧实现对照**把数值行为钉死。

## 三个脚本

| 脚本 | 验证范围 |
|---|---|
| `verify-collect-runs.js` | `collectPauseRuns` 单函数：29 个定向用例 + 20000 轮模糊 |
| `verify-three-funcs.js` | `alignWords` / `mergeRanges` / `scaledPauseMs`：32 个定向 + 60000 轮模糊 |
| `verify-pause-splicer.js` | **端到端整条管线**：10 段文本 × 6 组参数 × 真实 PCM，**逐字节**比对拼接结果与时间轴 |

`verify-pause-splicer.js` 是最重要的一支——它把旧版（git HEAD）和新版（当前文件）的**完整算法链**并排放，输入同一份 PCM，输出必须**逐字节相同**。

## 怎么跑

无需安装依赖（纯 Node，无 npm 包）：

```bash
node scripts/tts-verify/verify-collect-runs.js
node scripts/tts-verify/verify-three-funcs.js
node scripts/tts-verify/verify-pause-splicer.js
```

期望输出（三支都必须出现 ✅）：

```
✅ 全部等价
✅ 三个函数全部等价
总检查点: 346 | 失败: 0
✅ 新旧实现端到端完全等价（PCM 逐字节一致）
```

## 验证覆盖了什么

`verify-pause-splicer.js` 的 346 个检查点覆盖：

1. **标点识别**：连续标点合并（`……，`）、句末优先、右引号并入（`「好的。」`）、代理对（emoji / 生僻字）
2. **词级对齐**：重复词（`他说他说`）、TTS 归一化导致的搜不到（`100` 念成「一百」）、空词
3. **PCM 拼接**：6 组参数（含 `rate` 0.5/1/2、`volume` 0/0.7/1、停顿时长触发 10s 上限、停顿时长为 0）
4. **边界**：空 PCM、零采样率、单样本、整段无标点
5. **时间线**：句级与歌词级两种切分 × `totalMs` 0/5000/12000 × 有/无词级时间戳（走字符占比估算路径）
6. **时间轴反查**：`lookupAdjMs` / `lookupOrigMs` 往返一致
7. **随机模糊**：400 轮随机文本 + 随机 PCM，逐字节比对

## 改这个文件之后怎么用

1. 先改 `PauseSplicer.ets`
2. 把改动**同步**到 `verify-pause-splicer.js` 的 `NEW` 段（该段是手工镜像，不是自动 import——`.ets` 不能被 Node 直接 require）
3. 跑三个脚本，必须全绿
4. 再跑 `devecocli build --modules entry`
5. 真机验证：听书 → 检查①标点处有停顿 ②高亮/锁屏歌词与语音同步 ③块间无咔哒声

> ⚠️ 第 2 步的"手工镜像"是这套验证的**唯一薄弱点**：如果改了 `.ets` 却忘了同步脚本，脚本会拿旧逻辑自证。改完务必 diff 一遍 `NEW` 段。
